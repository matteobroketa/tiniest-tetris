# tiniest-tetris

Reproducible byte-golf record candidates for two precisely defined Python Tetris rulesets.

The repository treats source files as byte artifacts. GitHub Actions verifies their exact sizes and hashes, expands compressed payloads, runs a scripted oracle corpus, and exercises playable candidates in native CPython 1.6, 2.7.18, 3.8, and 3.14 environments.

### Scripted simulator

This is the fixed-input challenge published as **“Code Golf: Playing Tetris”** on Stack Overflow in 2010. It reads an exact 10×7 board, then drops fixed-orientation tetrominoes described by commands such as `T2 Z6 I0 T7`. It removes complete rows and prints the resulting board and score.

Declared limitation: the golfed programs read at most 99 bytes of commands, matching the historical Python approach. They are not interactive Tetris games and do not rotate pieces.

### Playable core

The playable candidates implement:

- 10×20 board;
- all seven tetrominoes in a fixed cycle;
- automatic gravity;
- left and right movement;
- clockwise matrix rotation;
- collision detection and locking;
- complete-row removal;
- termination when the next piece cannot spawn.

Controls are `a` = left, `b` = rotate, and `c` = right. The game has no score display, preview, hold, soft/hard drop, seven-bag randomness, levels, pause, wall kicks, or explicit game-over message. It is a minimal Tetris core, not a modern guideline implementation.

The 442-byte Python 3 experiment in `candidates/playable/py3/tetris_442_restricted.py` is excluded from the main table because its fixed 4×4 movement boundary is more restrictive than the 445-byte candidate.

## What CI proves

The workflow at `.github/workflows/proof.yml` performs four independent proof layers.

1. **Byte identity** — exact byte counts, SHA-256 digests, and trailing-newline state are checked against `proofs/manifest.json`.
2. **Payload identity** — each compressed candidate is decompressed by an independent Python 3 verifier and compared byte-for-byte with its readable payload.
3. **Scripted semantics** — the candidate is run against 33 committed vectors generated by an independent reference model, including the historical sample.
4. **Playable behavior** — a fake `curses` screen validates every rendered frame as a 20×10 grid, checks a deterministic 477-frame trace with six line-clear transitions and a fixed checksum, then runs 32 additional seeded games per runtime with a 10,000-frame safety bound.

The native runtime matrix is:

| Runtime | Provisioning method |
|---|---|
| CPython 1.6 | Built from the official source archive in a Debian Squeeze container |
| CPython 2.7.18 | Built from the official source archive in a Debian Squeeze container |
| CPython 3.8.16 | `actions/setup-python` |
| CPython 3.14.x (latest available) | `actions/setup-python` |

Each job uploads a proof log as a workflow artifact. The static job also writes a compact report to the GitHub Actions job summary.

CI proves that the committed files have the stated size and behavior in the stated environments. It cannot prove that no unpublished or unindexed smaller implementation exists. Record language should therefore use **“smallest publicly documented candidate located for this exact ruleset”**, not “mathematically proven world record.”

## Run the proofs locally

Current Python 3 environment:

```sh
bash tools/prove_current.sh
```

Historical interpreter containers:

```sh
image=$(bash tools/build_legacy_image.sh 1.6)
docker run --rm "$image" python -c 'import sys; print sys.version'

image=$(bash tools/build_legacy_image.sh 2.7.18)
docker run --rm "$image" python -c 'import sys; print sys.version'
```

The build scripts download source archives from `python.org`, verify their recorded checksums, build interpreters under `/opt/cpython`, and confirm that `zlib` is importable. Downloaded archives are ignored by Git.

## Run the Python 3 game

Use a terminal with `curses` support:

```sh
python3 candidates/playable/py3/tetris_445.py
```

The file requires Python 3.8 or later. Do not edit, re-encode, auto-format, or normalize line endings in any file under `candidates/`; several contain non-UTF-8 bytes and intentionally omit a trailing newline.

## Prior art and attribution

The scripted implementation is derived from Nas Banov’s 298-character Python answer to the 2010 Stack Overflow challenge. The challenge content predates April 8, 2011 and is distributed under CC BY-SA 2.5. Detailed attribution and modification notes are in `ATTRIBUTION.md`.

Other relevant prior art includes Nick Paz’s `tiny-tetris` business-card implementation and the 449-byte Python “Binary Tetris” entry on Code Golf Stack Exchange. Those programs target different specifications and are not direct byte-for-byte competitors with every candidate here.
